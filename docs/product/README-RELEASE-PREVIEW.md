# teamspeak-svc

**在 Minecraft 中保留熟悉的 Simple Voice Chat 操作，连接 TeamSpeak，与游戏内外的朋友交流。**

> **产品方向已确认，2026-10-29。** 负责人已回复“可以”，本文的目标及末尾建议默认值作为后续实施依据。它描述预期成品，不是当前版本功能已实现、已测试或已发布的声明；旧 README 与本稿冲突时按已确认产品方向修订，具体实现与发布支持范围仍需验证。

## 项目是什么

teamspeak-svc 是基于 Simple Voice Chat（SVC）的 Minecraft Fabric 语音扩展。

玩家继续使用 SVC 的语音界面、按键、PTT、语音激活、静音、音量和设备设置，同时可以选择 TeamSpeak 3 或当前 Minecraft 服务器的 SVC 服务进行通话。

使用 TeamSpeak 时，安装本扩展的 Minecraft 玩家作为独立 TS 用户进入频道，与原生 TeamSpeak 用户直接交流。不同 Minecraft 服务器的玩家连接同一 TS 网络、进入同一频道，也可以一起通话。

本项目包含客户端功能和按需启用的服务端功能，对外统一提供 teamspeak-svc 安装包。基础 TS 直连不要求 Minecraft 服务端安装本扩展，也不要求 Minecraft 服务端安装 SVC。

## 你可以用它做什么

- 在 SVC 原界面中管理 TS 服务器书签、连接、断开及切换频道。
- 使用同一套麦克风操作，在 TS 和原版 SVC 之间明确选择。
- 与原生 TeamSpeak 用户聊天，或与其他 Minecraft 服务器的朋友跨服通话。
- 在 UDP 受限时，使用服务器提供的 Minecraft 网络通道传输语音。
- 按参与者保存个人音量与静音设置，查看真实连接状态和麦克风发送目标。
- 保留已有音频增强入口和用户偏好，不在升级时擅自改变音效默认值。
- 在音乐扩展完成后，创建独立频道音乐 Bot、共同点歌，或由服务器长期托管音乐。

## 四种连接模式

TCP 模式使用当前 Minecraft 连接承载数据；TeamSpeak 端仍由中继使用其正常 UDP 语音协议通信。

| 模式 | 使用场景 | 玩家安装 | Minecraft 服务端条件 |
|---|---|---|---|
| **TeamSpeak / UDP** | 客户端能直接访问 TS，跨服交流的基础模式 | SVC + teamspeak-svc + 对应 Fabric 依赖 | 无本扩展或 SVC 的要求；外部 TS 服务可达即可 |
| **TeamSpeak / Minecraft TCP** | 客户端 UDP 受限，经当前 MC 服务器访问 TS | 同上 | 安装 teamspeak-svc，开启 TS 中继并配置允许的 TS 目标；服务端不必安装 SVC |
| **SVC / UDP** | 使用当前服务器原有语音服务 | SVC；安装本扩展后仍可选择此模式 | 安装并启用 SVC |
| **SVC / Minecraft TCP** | 当前 SVC 服务器提供 MC 通道传输 | SVC + teamspeak-svc，或兼容矩阵明确支持的客户端适配 | 安装 SVC + teamspeak-svc，并启用相应适配 |

选择 TCP 模式需要对应服务端支持；仅客户端安装无法让任意服务器自动成为中继。TCP 是网络受限时的可选方案，不保证比 UDP 延迟更低。

旧版独立 TS 隧道可作为历史兼容路径保留，不作为新部署的必装组件，也不将旧配置静默改成 MC 通道。

SVC-Extra 互操作与双装按明确的版本兼容矩阵说明。正常使用本项目自有 TCP 适配不要求另装 SVC-Extra；不能承诺所有版本任意混装。

## 连接如何选择

### 自动模式

目标选择顺序如下：

1. 玩家当前明确的选择：手动 TS 书签、指定 SVC、暂停或关闭全部语音。
2. 玩家为当前 Minecraft 服务器明确保存的后端覆盖规则。
3. 当前服务器提供、仍有效且已获用户授权的 TS 推荐。
4. 明确启用的本服本地 TS 自动目标。
5. 明确启用的全局 TS 自动目标。
6. 当前服务器可用的 SVC 服务。
7. 没有可用目标时，显示未连接，并提供手动 TS 入口。

服务器推荐只是一种配置来源。没有公告，不会取消用户自己的 TS 配置；服务器只有原版 SVC，也不妨碍玩家手动选择 TS。

上述顺序是目标选择优先级，不表示连接失败后可以悄悄试遍其他语音网络。未授权公告不参与自动连接；推荐地址变化不覆盖正在使用的手动目标。公告过期限制后续自动连接，不强制结束合法的手动 TS 通话。

在没有服务器 SVC 的情况下，玩家仍可使用客户端的语音前端，手动连接可达的 TS 服务器。

### UDP 不可用时

AUTO 传输优先尝试 UDP。网络超时且存在与所选 TS/SVC 服务匹配、用户允许的 TCP 路径时，可按策略重连到该传输，并显示变化。

密码错误、权限不足、封禁和协议不兼容会给出具体修正提示，不被解释成“UDP 被封”。强制 TCP 但没有对应服务端支持时，明确显示不可用。

TS 切换到 SVC 会改变通话对象。正在讲话时先暂停发送并提示，按用户明确操作或已保存的切换规则恢复；不能在 PTT 按住或语音激活连续发声时悄悄换网络。

### 三个不同操作

| 操作 | 预期效果 |
|---|---|
| **断开 TeamSpeak** | 结束 TS 连接，暂停麦克风上传，不自动改为 SVC；等待玩家明确恢复或选择 |
| **切换至原版 SVC** | 选择当前服务器的 SVC，确认可用后，在明确的发言边界恢复发送 |
| **关闭全部语音** | 停止扩展管理的 TS/SVC 语音收发及本机主持音乐；保留配置与用户音量/静音偏好，不关闭游戏本身的声音 |

暂停与关闭状态不会被新公告、自动重试或切换 Minecraft 服务器自动撤销。

麦克风始终只有一个明确的语音发送后端。界面显示“发送至 TeamSpeak / 发送至 SVC / 未发送”以及等待或失败原因。

## 熟悉的操作，明确的频道范围

### TeamSpeak 页面

- 书签新增、编辑、删除、自动连接和手动连接。
- 独立服务器凭据、昵称及本地 TS 身份引用。
- 频道浏览、搜索/滚动、加入、密码输入和权限错误反馈。
- 在权限允许时创建频道，填写名称、父频道和可选密码。
- 用户列表、说话状态、个人音量和静音。
- 实际连接地址、传输、频道、发送状态、重试与故障原因。

TS 服务器的频道权限继续由 TS 管理员控制，本扩展不绕过密码或权限。

### 两种服务的通话范围

**SVC 模式**保留当前 SVC 服务的距离语音、群组与服务器规则。

**TS 模式**以 TS 频道及其权限组织通话。进入同一频道的成员可以互相交流，不会因为分处不同 Minecraft 世界或服务器而自动变成附近语音。

SVC 群组交互可以在具备映射配置与权限时联动到 TS 频道，作为可选兼容模式；不能假设所有 TS 服务器都允许自动创建频道，也不把所有 SVC 群组强制永久映射到 TS。

TS 默认遵循原生频道操作习惯：管理员正常移动玩家，服务器确认后接受新频道。玩家明确锁定频道时，被移出目标会暂停发送并提示；未确认、失败或歧义的移动不会将语音送到错误频道。

个人音量跟随稳定的参与者身份，同名用户不共用音量。Minecraft 账号关联、名字和皮肤展示不应改变实际播放身份；未经验证的名字不冒充身份认证。

## 跨服，以及“互通”的边界

### 本扩展玩家与原生 TS 用户

这是项目的核心能力：

```text
MC 服务器 A 的扩展玩家 ─┐
MC 服务器 B 的扩展玩家 ─┼─ 同一 TS 服务器、同一频道
原生 TeamSpeak 用户 ────┘
```

原生 TS 用户正常使用自己的客户端，无需安装 Minecraft 模组。仅使用 TS UDP 的玩家，不需要当前 MC 服务器配合。

TS MC 通道绑定当前 Minecraft 连接；换服或断开 MC 会使该中继失效，需要重新建立适用的连接。不能承诺所有模式换服都无缝持续。

### 普通 SVC 玩家与 TS 用户

仅支持选择两种后端，并不会让未安装本扩展的 SVC 玩家自动进入 TS 网络。

真正的 SVC↔TS 媒体互通需要明确的服务端媒体网关。它是否成为必做功能及第一版范围仍待负责人确认；若实施，优先由 teamspeak-svc 自身提供可选服务端能力，并由管理员明确配置群组、频道和权限，默认关闭。

## 音乐：独立频道服务

音乐是计划内扩展，按版本逐步交付。它与基础通话使用同一产品入口，但有自己的身份、连接、队列和权限。

### 客户端临时音乐 Bot

主持玩家在游戏内开启频道音乐，创建独立 TS Bot 加入指定频道。同频道的扩展玩家与原生 TS 用户都能收听。

- 支持添加曲目、查看队列、点歌者、暂停、继续、下一首、清空及停止。
- 玩家麦克风继续正常通话，音乐不会注入玩家 PTT，也不与玩家共用 TS 身份或连接。
- TS UDP 可直接建立 Bot 会话；MC TCP 需要服务器允许独立第二会话。
- 音乐房间绑定 TS 服务器和频道，来自不同 MC 服务器的参与者可以共享音乐及受权限控制的队列。
- 主持端明确管理房间，不自动抢占别人的 Bot，也不通过昵称判断主持权。
- 本地音乐音量、静音和讲话时自动压低只影响自己的收听，不改变整个频道的发送音量。

音源分阶段提供：先完成明确授权的本地文件与基础播放，再接入有使用权限的网络音源和可选提供方。搜索结果不等于可获取、可转播的音频，不承诺默认支持全部商业音乐平台。

### 可选服务端音乐托管

管理员可以在统一扩展中启用 Music Host，持久保存队列和权限；主持玩家退出后仍可继续服务。

TS 音乐托管不应强制安装 SVC。客户端临时 Bot 和服务端托管使用共享音乐逻辑，切换主持端时明确交接，不能同一队列两端重复播放。

**本稿建议的默认行为：**客户端主持人退出游戏、断开自己的 TS、切换 SVC 或关闭全部语音时，同时停止本机主持的 Bot；其他人或服务器主持的 Bot 不受其本地操作影响。是否提供明确的“音乐独立持续运行”选项，见待确认项。

## 玩家与管理员如何安装

### 玩家

1. 安装发布兼容矩阵列出的 Minecraft/Fabric 版本、Fabric API、SVC 和 teamspeak-svc。
2. 进入 SVC 的 TeamSpeak 页面。
3. 使用自己的书签，或查看并授权服务器推荐的目标。
4. 选择自动、UDP 或服务器实际支持的 TCP 路径，确认当前频道与麦克风目标后通话。

服务器没有本扩展时仍可使用 TS UDP；没有 SVC 服务端时仍可手动使用 TS。

### 管理员

玩家和服务端使用统一发布的 teamspeak-svc 包，服务端功能按需启用：

| 功能 | 额外条件 |
|---|---|
| 公告 TS 推荐 | 配置推荐目标；客户端仍需按信任策略接受 |
| TS MC-TCP 中继 | 配置允许目标、权限、连接数与流量限制；服务端能够访问 TS |
| SVC MC-TCP | 安装并启用兼容 SVC 服务端，使用按玩家适配 |
| TS 音乐托管 | 启用音乐宿主、配置 TS 身份、目标频道和音源/控制权限；不要求 SVC |
| 可选媒体桥接 | 尚待确定；若实施，需 SVC、TS 与管理员明确授权的桥接范围 |

安装服务端扩展不等于自动启用所有能力。没有启用的功能不被公告为可用；普通 UDP 路径应继续正常工作。

## 产品发展方向

1. **基础正式版**：可靠 TS/SVC 通话、原界面操作、书签/频道/用户控制、四种连接模式、统一可选服务端与清晰故障反馈。
2. **音乐扩展**：基础音源/编码 → 临时独立 Bot 与最小队列控制 → 完整多人点歌体验 → 可选服务端托管。
3. **跨协议增强，待确认**：普通 SVC 用户与 TS 用户的受控媒体互通，以及是否开放 SVC 音乐输出。
4. **跨平台长期目标**：网页/手机通过 WebRTC 等方案接入同一身份与频道体系。网页音频接入还需要相应信令与媒体服务，不是当前 MC 通道的自然延伸，也不变成基础客户端必装依赖。

所有正式发布功能必须列明兼容版本、部署条件和已完成的测试。开发阶段代码存在、构建成功、单项自动化通过，不单独等于用户场景可用。

## 已确认的产品默认值与长期边界

以下建议已随本稿获得负责人确认，作为默认产品规则。表中明确保留为长期/可选的功能不会因此自动成为首个正式版必交付；这些默认值也不代表实现已经完成。

| 问题 | 本稿采用的建议 |
|---|---|
| 基础正式版与音乐是否同一版本发布？ | 基础稳定版先发布，音乐分阶段扩展；音乐仍属于项目主线，不从长期目标删除 |
| 自动连接的排序是否正确？ | 当前显式选择/本服覆盖优先；已授权服务器推荐高于普通本地/全局自动目标；无公告时自己的目标继续生效 |
| TS 与 SVC 是否允许同时收听？ | 默认只收听明确选中的后端，双收听作为单独显式选项；麦克风始终只发一个后端，不从当前实现反推产品决定 |
| TS 模式是否默认需要附近语音？ | 建议默认按 TS 频道通话；距离语音保留在 SVC 模式，可选群组映射不等于跨服位置同步 |
| 离开玩家语音后，本机音乐是否继续？ | 建议默认停止并提示；如需独立持续运行，增加明确选项，不能隐藏播放 |
| 音乐主持权是否必须全频道绝对唯一？ | 首期明确 owner/房间、无自动争抢；如要求全网强排他，需要额外权威协调设计 |
| 普通 SVC↔TS 媒体桥接是否属于必交付？ | 当前保留为可选增强，需确认是否必做及首期映射范围 |
| 网页/手机是否首个正式版必备？ | 建议长期独立阶段，不阻塞 Minecraft/TS 基础正式版与音乐 |

**当前开发状态提示：**本稿不替代进度报告。最新复核仍有产物装载配置、TS/SVC 通道闭环和音乐引擎正确性问题待修复，客户端验收暂缓；应在这些问题解决、相应功能验证后，才把本稿目标改写成实际发布说明。
