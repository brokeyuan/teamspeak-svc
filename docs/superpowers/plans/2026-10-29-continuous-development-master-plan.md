从当前实际源码继续，首先处理已确认缺陷和未完成接线，再进入统一发布，然后沿已确定的路线推进传输及音乐功能。**阶段完成是检查点，不是默认交接点。**

下一次主要交付范围为 **N0–N7 工程收尾 + M7 统一可选服务端实现**。如果这两部分通过工程检查且仍能继续工作，就推进后面的已确定任务，不因已经达到这两个阶段而主动停止。

“尽可能多做”以完整、可验证的功能增量衡量，不以新增类数或文档页数衡量。不得一次铺设所有阶段的占位接口、空开关和测试替身，然后宣称长期功能已支持。

本文件供实施 AI 执行；当前编写任务书的会话仍只负责指导，不修改业务源码。

## 4. 依赖与局部阻塞处理

- A 是 B 的主要前置；确认的错误发送、资源恢复缺陷不能因扩大范围而放置不管。B 的无关环境隔离工作可以在 A 个别外部验证等待期间进行，但不能因此宣称 A 完成。
- B 提供自有可选服务端基础，C/D 复用；不新增第二个要求管理员另装的公告或中继模组。
- C 优先于 D。C 某个 TS 实网实验不可执行时，保留其未验证状态，可以继续 D 的独立源码研究和适配工作，不伪造 C 已通过。
- F 不依赖 C/D 的全部客户端验收，可以在传输的外部验证等待期间推进。G 的 Bot 可先用 TS UDP；走 MC 中继时必须明确支持第二受控会话，不能占用玩家会话。
- G 的可信跨服控制协议未被证实时，可以完成独立 Bot、最小本机控制、生命周期及队列测试；跨服控制保持具体阻塞项，不把昵称或 JSON 自报身份临时当可信凭据。
- I 依赖实际可复用的音乐引擎和权限队列。未完成主持权设计时不得通过复制队列让客户端和服务器同时播放。
- J 的产品范围待确认只阻塞 J，不能阻塞 A–I。K 的部署选择也不阻塞 Minecraft 与 TS 的核心功能。

对每个阻塞项记录：具体问题、已有证据、阻塞哪些任务、能继续哪些任务、需要什么才能解除。不要只写“环境缺失，全部停止”。

## 5. 进入一个较后阶段时的必要动作

N0–N7 和 M7 已有详细任务书。P6/P5/Music 仍含需要源码/原型确定的设计，不得直接把备忘录中的建议写成既有协议事实。

开始这些阶段时，在当前任务内完成以下步骤，然后继续实施，不因常规技术细化再次要求用户授权：

1. 阅读该阶段涉及的实际源码、依赖与现有未提交变更，固定兼容版本。
2. 在本阶段记录中列出待修改文件、接口、数据格式、线程归属、资源上限、错误处理、可执行测试与回滚方式。
3. 先做能判定技术路径的最小验证；例如 TS 中继的数据报往返、SVC 协议封装兼容、无 SVC 的音乐编码。
4. 根据验证结果冻结最小可行实现，完成一条真实生产路径，再扩充功能；不为了所有后期需求一次重写核心。
5. 对本阶段改动运行针对性测试，通过后检查受影响的既有回归，提交并更新状态，再继续下一项。

具体队列上限、超时、帧格式和库选择应有依据并记入阶段记录，不能留空。但若选择涉及新的必装部署组件、全网主持权保证、付费服务、用户音频受众变化或 P7 范围，应将该决定单列，等待负责人选择，同时继续无关任务。

## 6. 阶段检查点和验收暂缓

每阶段保留三列：实现状态、工程验证、客户端验收。第四列可记录真实服务端/TS 互操作证据，避免把所有非客户端检查一起推迟。

- 本轮不要求用户启动客户端、提供截图或设备、陪同通话；这些检查按原编号标“用户主动暂缓”。
- ABI 核对、单元/回归、实际 codec/handler 调用链、构建、可用的专用服务端启动和本地回环测试照常执行。
- 工程验证足以支撑下一项工作时继续开发；缺失真实客户端证据不是阶段间自动停点。
- “可以继续开发”不等于产品已验收，也不等于兼容所有版本、可稳定发布或已实测双向音频。
- 尚未完成的 transport/provider/网关不能公告为可用能力。默认关闭未达到对应启用条件的可选功能，且保留明确不可用原因。
- 一个未验证的实验不得默认取代既有稳定路径；继续保留原生 SVC UDP 和 TS UDP 的可用配置及回退边界。

## 7. 何时继续、何时交接

完成一个任务或一个阶段、编译成功、已经写出足够多代码，都不是默认停下来的理由。完成当前检查点后，查看队列，继续下一项已明确且具备条件的工作。

可以结束当前执行并交接的情况：

- 用户明确要求暂停或改变范围。
- 可执行的已确定工作已经完成，剩余都依赖具体的用户决策或不可获得的外部条件。
- 执行环境或上下文/运行限制使本次无法继续；先保存清晰的进度和下一条可执行任务，不把未完成项目写成完成。

必要时按以下格式持续维护 `review/continuous-development/STATUS.md`，让下一次从准确位置恢复：

```text
基线 / 当前提交：
当前阶段 / 当前任务：
已完成的生产路径：
本次实际测试与证据路径：
客户端暂缓项：
局部阻塞及不受影响的任务：
下一条具体动作（文件、方法、验证命令）：
本轮新增或修订的技术决策：
```

每完成一个阶段更新状态和交付摘要，但继续工作。最终交接报告汇总本次实际推进范围，不重新复制整份长期规划，也不把“以后可以做”写成已经交付。

## 8. 必须始终保留的产品边界

统一 teamspeak-svc 发布；MC 服务端可选；无公告/无 SVC 服务端仍支持手动 TS；原 SVC 操作体验；单一玩家麦克风发送后端；明确的三种离开/切换操作；正常 TS 管理员移动可跟随；四种模式独立说明部署条件；TS 直连不等于普通 SVC↔TS 互通；音乐身份/会话与玩家独立；不强制外部 Bridge。

本次扩大的是持续推进的工程范围和执行跨度，不是允许跳过这些要求，也不是把尚待确认的长期设想全部视为无条件实施决定。
