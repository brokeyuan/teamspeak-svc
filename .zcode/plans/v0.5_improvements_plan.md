# teamspeak-svc v0.5 改进清单实施计划（TCP 隧道/文字互通/抖动缓冲/GUI/射线可视化）

## Repository Research
- `Ts3Connection.java`（teamspeak-svc/.../ts3voice/）：`connect()` 直接 `new DatagramSocket()+connect()`，`sendRaw` 用 `DatagramPacket`，`recvLoop` 阻塞 `receive`，`stop` close —— socket 未抽象，TCP 化需引入传输层接口。
- **SVC 2.6.25 无群组文字聊天**（`GroupChatManager` 仅 HUD 图标渲染；2.6.25 jar 无 GroupMessage 类）——"文字桥接"实为**新增** MC↔TS 文字互通，非桥接已有功能。
- TS3 文字：voice 命令通道 `sendtextmessage targetmode=2 msg=...`（频道）；入站 `notifytextmessage`（含 invokername/msg/targetmode）——当前 `Ts3VoiceClient.onCommand` 未处理该通知。
- 抖动缓冲：SVC 原生 `AudioPacketBuffer(int packetThreshold)`（common-client `AudioChannel` 构造中 NEW）；SVC-Extra `AudioChannelMixin` 用 MixinExtras `@WrapOperation` 按容忍度调大阈值。
- 射线可视化：MC 26.3 内置 `net.minecraft.gizmos.Gizmos.line(...)`；SVC-Extra `MinecraftGizmoMixin` 注入 `LevelRenderer.collectPerFrameRenderThreadGizmos`（980B，轻）。已缝合的 `RayTracedReverb` 保留有 `debugRays`/`showDebugRays`。
- 信标链路已通：tsbridge `BeaconSender` → 客户端 `TsVoiceManager.onBeacon`（现 payload：host/port/channel/backendMode）。
- tsbridge 配置 `mode` 单选（bridge/group-sync）；隧道需作为可叠加能力并存。

## Approach
- **TCP 隧道**：客户端把 Ts3Connection 的 socket 依赖抽象为 `TsTransport`（send/receive/close），UDP=现状包装；TCP=定长帧（4B 长度+载荷）流。隧道服务端做进 tsbridge（`tcpTunnelPort` 配置，任何 mode 下可开）：每 TCP 连接绑定独立本地 UDP socket 与 TS 互通（TS 回包按来源 socket 路由回对应连接）。信标 payload 增加 `tunnelPort`；客户端 `transport: "udp"|"tcp"`（默认 udp）。
- **文字互通**：TS→MC 用 `notifytextmessage` → 聊天栏 `[TS] 名: 文本`；MC→TS 用命令 `/tsvoice say <文本>`（原版无群聊 UI，不做界面深集成）。开关 `chatBridgeEnabled`（默认开）。
- 逐项独立可关（零回归要求：全关 = 0.4.3 行为）。

## Dependencies and Considerations
- TCP 帧协议两端必须同版（客户端 0.5.0 ↔ tsbridge 0.3.4）；旧 tsbridge + 新客户端 → 信标无 tunnelPort → tcp 模式报错提示回退 udp。
- 隧道下 TS 看到的源 IP=隧道机器（日志/封禁语义变化）；每连接 2 线程 + 1 UDP socket。
- MixinExtras（WrapOperation）随 Fabric Loader 0.20 自带，无需新依赖。
- TCP 通道无空闲（TS3 协议自带 1s ping），无需应用层心跳。

## Risks
- TCP 队头阻塞增延迟抖动：定位弱网兜底，文档说明；UDP 恒为默认。
- 隧道线程泄漏（连接异常断开）：per-conn 资 try/finally 全回收 + socket close 级联。
- notifytextmessage 也会收到 server 模式消息：按 targetmode==2 过滤 + 过滤自身回显。
- AudioChannelMixin 目标方法签名随 SVC 更新：defaultRequire=0 缺失时静默跳过（保持原缓冲）。
