# teamspeak-svc 审查问题逐一修复计划

## 目标
按审查报告修复全部高危 + 中危 + 低危清理 + 文档，tsbridge 侧协议栈本次不动。修复顺序按“风险×收益”分 6 个阶段，每阶段可独立构建验证。

## 关键新发现（已纳入计划）
1. `ConfigScreen` 密码框从未用 `entry.serverPassword` 回填，且保存时在 `!editLocked` 分支无条件写入——打开 GUI 点“完成/连接”会把已存密码覆盖为空（D1 由中危升为高危）。
2. `AudioExtraScreen` 的唯一入口是 `VoiceChatScreenMixin.java:70`，不是 ConfigScreen；且从未 `setParent`，关闭后不回 SVC 界面。

## 验收标准（rule）
- AC-1 `gradlew.bat build` 成功，产物 jar 可加载。
- AC-2 带密码群组：注入模拟 `getGroup()` 每次新对象的场景，tick 不再每轮清空密码，密码在 6s 窗口内可用。
- AC-3 `/tsvoice status` 与 `/tsvoice connect` 不再抛 `MissingFormatArgumentException`。
- AC-4 GUI 打开/保存不再清空已存密码；密码框掩码显示。
- AC-5 `duckingLevel`/`aecDelayMs`/NVIDIA 路径/`networkToleranceMs` 修改后经 reload 生效。
- AC-6 AEC 处理结果写回发送数组（静态单测/断点验证）；reconfigure 不再泄漏 native APM。
- AC-7 `DuckingManager.tick`、`RayTracedReverb.tick` 有且仅有一个主线程调用点；无跨线程世界访问。
- AC-8 QuickerLz 对畸形输入抛 `Ts3VoiceException`，连接不中断。
- AC-9 密码/身份文件在 POSIX 下为 600；日志无明文密码。
- AC-10 README/ROADMAP 与代码一致（命令、配置、版本）。

## 非目标
- 不回移协议栈修复到 tsbridge、不抽共享模块。
- 不引入测试框架/不改构建体系（除版本号）。
- 不实现 whisper 经 TS、不做 3D 声源 TS 侧插件。
- 实机多人语音联调需人工执行，本环境以构建+静态验证为准。

## 执行方式
按 T1→T29 顺序逐项实施；每完成一个阶段跑一次 `gradlew.bat build`；全部完成后进入独立 Review，发现可执行问题回到任务队列修复，直至评审 pass。
